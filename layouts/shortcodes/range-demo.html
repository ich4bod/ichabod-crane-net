Ask for the missing bytes

Ten ASCII characters stand for ten bytes. The saved prefix always comes from ABCDEFGHIJ. This is an arithmetic example, not a network request or a download manager.

Both files have ten bytes. The server can replace the uppercase file with a lowercase one while the saved prefix still belongs to the old version. A matching length does not make a matching file.

The saved strong entity tag is "v1". If-Range asks for a tail only while that version still matches. A changed version returns a complete file in this example; the client replaces its prefix instead of appending.

Current complete file
ABCDEFGHIJ
Saved prefix
ABCDEF
Request
Range: bytes=6-
Request validator
If-Range: not sent.
Response status
206 Partial Content
Response range
Content-Range: bytes 6-9/10
Response body
GHIJ
Assembled file
ABCDEFGHIJ

The bytes join the original file.

Ask at the two ends

A ten-byte file has offsets zero through nine. Starting at zero can request all ten bytes as a range. Starting at ten is beyond the last byte. This example chooses a 416 reply with no representation bytes; real error responses can have a separate explanation body.

Request
Range: bytes=0-
Chosen reply
206 Partial Content
Returned extent
Content-Range: bytes 0-9/10
Representation bytes
ABCDEFGHIJ
When the server sends the whole file

A server may ignore a Range request and send the whole representation. This switch chooses that allowed response for the example; it is not a failed validator. The client must replace its saved prefix when it receives the complete file.
